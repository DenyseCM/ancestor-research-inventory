# Ancestor Research Inventory (ARI™)

**Everything found on one ancestor, in one report, in plain files the researcher owns.**

The Ancestor Research Inventory is a report format for family history research, created by **Denyse Allen** at **[Chronicle Makers](https://chroniclemakers.com)**. This repository holds the format: its seven sections, what each one contains, and why each one is there.

**Canonical home:** [chroniclemakers.com/ancestor-research-inventory/](https://chroniclemakers.com/ancestor-research-inventory/)

---

## The seven sections, always in this order

| # | Section | File | Holds |
|---|---|---|---|
| 1 | **Index** | `index.md` | Who this person was. Names, settled facts, each traced to a record |
| 2 | **Timeline** | `timeline.md` | Life events in date order, each tied to its source |
| 3 | **Sources** | `sources/` | One file per record examined, sorted by the date the record was created |
| 4 | **Conflicts** | `conflicts.md` | Every disagreement between sources, resolved or open |
| 5 | **Research log** | `log.md` | What was searched, how, and what came back — including nothing |
| 6 | **Research narrative** | `narrative.md` | The researcher's own account of the work, in first person |
| 7 | **Research Quality Check** | `quality-check.md` | The result of the check run on the research |

Full definitions and the reasoning for each section: **[SPEC.md](SPEC.md)**
Blank starting files: **[template/](template/)**

## What is here and what is not

**Here:** the report format, the shared vocabulary (confidence labels, result labels), the rules every ARI follows, and blank templates.

**Not here:** how conclusions are reached from the evidence, the criteria of the Research Quality Check, or the tools that build an ARI. Those are Chronicle Makers tools. An ARI can be built by hand or by any tool. This repository defines what the finished report contains.

## Building something?

If you are building software that reads or writes ARIs — or you have tried the format and found an edge it does not handle — open an issue. Input from people building things is welcome.
